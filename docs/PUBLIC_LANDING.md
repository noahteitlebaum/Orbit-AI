# Public landing and registration — October 18, 2026

Signed-out `/` shows a concise headline, value proposition, three benefits and Get Started links to `/signup`. Log In goes directly to `/login`. Forms, institution selection, the interactive preview and provisional pricing are removed from the homepage. Existing Wordmark, OrbitBackdrop, provider logos and design tokens are reused.

`/signup` is the single institution-aware registration page. The existing institution configuration supplies the initial list; unlisted Canadian institutions can use manual entry. Western reveals the existing password/account creation and inline email-code verification flow. Its form stays mounted when the institution changes so verification progress is retained. Other selections show one shared waitlist form with institution-specific copy; they do not create accounts. Waitlist errors and success remain inline. Changing institutions resets waitlist form state so an earlier submission cannot show success for a different institution.

The signup action requires the Western institution ID and exact @uwo.ca email server-side, then stores the canonical institution ID/name in Supabase auth user metadata. Metadata is informational, not an access grant: verified email and existing early-access checks remain authoritative. Existing login, reset, authenticated-home routing and account waitlist routing are unchanged. Login’s registration link now points to `/signup`.

Public waitlist interest remains separate from accounts, billing and app access. The existing endpoint resolves configured school IDs to canonical names, validates trimmed manual names (2–120 characters, letters required, no control/format characters or angle brackets), and records the institution in the existing private table through the service-only RPC. Manual institution names are self-reported; this does not verify institutional status, enrolment or Canadian location. No schema migration is required by this change. Previously stored entries remain unchanged; duplicate email submissions still return the same outcome without overwriting the original institution.

Existing consent, origin checks, body-size limit, honeypot, keyed-IP rate limiting and RLS remain in place. Raw IPs and emails are not logged. Hosting must overwrite forwarded IP headers. No email verification or automated invitation sender exists for the public interest list; success means interest stored, not an email sent or an access date promised.

Migration0016, the service key and Supabase URL remain prerequisites for collecting interest. Privacy, terms and contact routes retain the existing pending/approved-URL behavior. Payments remain disabled. No university SSO or affiliation is claimed. Live email delivery and production Supabase configuration require staging validation with synthetic accounts.

Desktop (1280px) and phone (375px) layouts were inspected; homepage and registration had no horizontal overflow at 375px. The test service and screenshots are outside the repository. Production email delivery, hosted-origin behavior and real Supabase persistence still require staging verification.
